# BuffRadar 1.15.38 — audit follow-up

This ledger preserves the evidence for the unpublished 1.15.38 candidate.
The changes ship as **1.16.0**; use the [release matrix](FOREVER_1.16.0_VALIDATION.md)
for the new version's distinct ZIP and checksum.

This ledger groups the 32 follow-up items by subsystem. It compares the
candidate with v1.15.37 (`a02f3ebcafb663352d1e6038cb95e8e3c3eaf41e`).
Unless marked otherwise, the evidence is from Lua 5.1 fake clients, static
checks or local packaging. Passing those checks does not verify secure
execution, rendering, chat delivery or native timing in WoW: Forever. See
[the candidate matrix](FOREVER_1.15.38_VALIDATION.md) for the exact ZIP and
pending Windows and live checks.

In the tables, **audit smoke** means an isolated case in
[`tools/audit51.lua`](../tools/audit51.lua), driven by
[`tools/smoke51.py`](../tools/smoke51.py) in all applicable setups. The Retail
TOC is a regression fixture, not a supported release.

## Startup, persistence and reviews

| # | Recommendation and change | Evidence and remaining limits |
|---|---|---|
| 01 | **Verify the edition at startup.** The shipping TOC loads `Forever.lua` before `Data.lua`. The declared interface and `GetBuildInfo` must both identify Interface 16001. An unsupported install leaves SavedVariables untouched and does not initialize the cast UI, pull listeners or the Options category. | Unsupported-build and wrong-edition audit smoke; supported TOC startup in both Forever setups; packaged `/br selftest`. WoW itself may stop an out-of-date TOC before addon code runs. |
| 02 | **Park only an owned macro.** Recognize BuffRadar-generated bodies, keep the combat/death guard, and recheck the body before editing. Park ineligible actions without overwriting a same-name user macro. Defer incompatible-client parking until combat ends if needed. | Macro migration, edit, length and stale-target smoke; unsupported startup and refresh fault audit cases. Game lockdown and macro editor deferral still require live testing. |
| 03 | **Validate on a detached save.** `SavedVariables.lua` rebuilds known nested maps and validates finite numbers, enums, keys, booleans, strings and anchors before publishing schema 23. Buff masks, custom pairs and spell IDs use shared validators. | Legacy v2 and v22 fixtures, corrupt-save fuzz, and tests for nested aliasing and malformed points. Named profile text is bounded on load and validated again when parsed for use. |
| 04 | **Preserve future saves.** Use a sanitized working copy when `dbVersion > 24`; leave the original global and unknown fields untouched. Changes only last for the session. | Future schema fixture changes the working copy, including nested values, without modifying the original object. Real logout/reload persistence is a live check. |
| 05 | **Cap deliberate storage without dropping the user's data.** Limit to 32 profiles (4,000 bytes each) and 192 permanent ignores. Reject a save, add or paste that would exceed a limit without partially applying it. Preserve pre-existing overflow and allow only explicit `/br storage delete …` recovery. | Audit smoke: full profile store, atomic ignore batch and BR1 cap rejection, overflow recovery followed by reload. An intentionally preserved save may still exceed the caps on disk. |
| 06 | **Bound retained state and telemetry.** Keep 64 character anchors, 192 stat keys, 50 history entries, 50 persisted offenders, 128 current-session offenders and 20 group-spell pairs. Record each offender GUID once per group, even when two players have the same display name. | Cap fixtures and deterministic load/prune paths, offender fold/rename/same-name cases. Older name-keyed offender totals remain labeled legacy rather than being guessed onto a GUID. |
| 07 | **Rescue bad window placement.** Reject malformed anchors and non-finite offsets; recover from an off-screen point or a failed `SetPoint` with a safe default. | Audit startup tests force an impossible point and a genuine frame placement refusal. Native drag, display-scale and UIParent coordinates still need a field pass. |
| 08 | **Share preference side effects.** Quick Setup, UI controls, slash commands and profile application use common readiness invalidation. Enabling Lite or disabling forecasts, pull flash, sync or optional watches retires the relevant state without unrelated edits. | Setup, profile, Lite and combat-debuff smoke; pull audit checks that turning off flash preserves a still-enabled forecast and turning both off clears it. |
| 09 | **Review BR1 settings pastes before applying.** Parse a bounded, complete string; show normalized changes, allow Edit paste or Cancel, and require another review if compared values change. Apply locally; keep unrelated geometry and history. | Settings round-trip, fuzz, paste length/cap/cancel and review drift audit cases. Historical BR1 formats that meet the completeness checks remain readable. |
| 10 | **Make profile replacement explicit.** `/br profile import` reviews a BR2 draft, reports the same-name collision and affected auto-profile contexts, supports renaming and rechecks before storing. Saving does not load the profile. | Audit cases change a profile during review, rename to a new name, then explicitly replace the original and retain its mapping. Profiles remain limited snapshots, not character backups. |
| 11 | **Make plan imports local by default.** Review assignment, blessing and auto-profile changes and warn about missing named profiles. Apply locally without sending; export remains copyable. | Plan parser/round-trip, review cancel and audit send-count assertions. Only assignments and blessings can be shared; mappings always stay local. |
| 12 | **Recheck plan-sharing authority and scope.** Explicit **Apply and share** needs sync, current role and a unique, complete roster. Capture leader and membership epochs; refuse stale confirmation after replacement, leave/rejoin or handoff. Reordering alone is not a change. | Audit cases exercise churn back to the same roster, leader handoff, pure reorder and duplicate GUID refusal. Submission counts are not acknowledgements. |
| 13 | **Retire legacy remote plan overlays.** Track sender GUID, scope and prior local value for legacy `ASSIGN`/`BLESS` updates. Restore prior values on membership/authority loss or sync-off without clobbering a subsequent local edit. | Legacy ownership audit, trust checks, and 22 two-client coordination scenarios for SYNC v3. Legacy messages do **not** have the v3 generation proof; a late message from a currently authorised sender may be accepted. |

## Observations and cast eligibility

| # | Recommendation and change | Evidence and remaining limits |
|---|---|---|
| 14 | **Distinguish absent, restricted, and incomplete aura data.** Protect modern reads and legacy tuples. Separate explicit list termination, zero returned values, unreadable fields and API errors; bound index scans to 40 slots. | Aura read/refusal/tuple cases and API-chaos smoke. A cap or refusal is not proof of missing auras; live secret-value behavior is pending. |
| 15 | **Avoid English matching on Forever.** Recognise a finite catalogue of food, flasks, drinking and world buffs by spell ID or client-resolved names. Report unknown counts separately and avoid claiming expiry without a readable timer. | Localized aura and legacy tuple audit fixture, world buff and drinking smoke. This is not a complete Forever spell catalogue; IDs and live coverage need field samples. |
| 16 | **Guard optional consumable and harmful-aura watches.** For the requested optional ID, accept an exact helpful result or fall back to the helpful index scan. Debuffs on player/focus stay read-only and separately bounded, including in combat. | Helpful vs harmful and unclassified ID cases, bounded scan, gated debuff/event smoke and combat timing counters. Restrictions may hide real auras; no Soulwell or encounter prediction claims. |
| 17 | **Check temporary coating applicability.** Inspect main/off-hand item class and equip location. An empty slot, shield or non-coatable weapon is not missing a coating; unreadable item information is unknown. | Audit smoke covers a nil slot, shield, coatable off-hand and unreadable details; Personal and row watch cases. No permanent-enchant check. |
| 18 | **Separate Fortitude family observations from policy.** Use presence/expiry observations for Fortitude and Prayer, then apply rebuff and forecast thresholds; conserve known coverage when alternate timing is incomplete. | Forecast/family alternate, expiry and unknown smoke cases; retained observation audit. This is an incremental Fortitude separation, not a rewrite of every buff's policy. |
| 19 | **Apply recipient-rank rules consistently.** Explicit rank and ID, secure spell and target paths reject a known too-low recipient and can choose a lower eligible rank. | Rank audit exercises rejection and lower-rank selection in target, ID and rank modes. Plain name macro mode intentionally leaves final rank choice to WoW. |
| 20 | **Use a shared group-cast gate.** Automatic, Shift-click and group key paths require a suitable current target, known spell, group spell range, group rules and applicable reagent counts; otherwise use an eligible single cast. | 21 | **Keep pets and reused tokens safe.** Treat supported player/party/raid pet tokens as single-target recipients, do not include pets in group-cast need counts, and check live GUIDs before acting. Actual protected pet casts are unverified. |
| 22 | **Prune GUID observations and avoid false drop alerts.** Reuse bounded scan maps, retain last confirmed state through unreadable reads for that member, and remove expired markers or departed GUIDs. | Unknown → confirmed loss, death → resurrect, expiry TTL and member-replacement audit steps. Offline observation does not prove live detection frequency. |
